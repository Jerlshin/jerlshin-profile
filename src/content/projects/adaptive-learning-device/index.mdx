An adaptive learning system is only adaptive if it responds within the span of a learner's
attention. That constraint is what makes this a hardware problem rather than a model problem: a
round trip to a hosted model is fast enough on a good connection and useless on a bad one, and the
classrooms this was built for do not get to choose which they have.

## Approach

The device runs its reasoning locally, on a **distributed Raspberry Pi cluster** rather than a
single board — the same edge-inference architecture that placed 5th nationwide among 2,500+
participants at the [BITS Pilani Open Challenge](/achievements).

- **Fine-tuned LLMs** supply contextual reasoning over the learner's current state — what was
  attempted, what was missed, and what the next question should therefore be.
- **LangChain** orchestrates the retrieval and prompting steps so that lesson content, learner
  history, and the model call stay separable components rather than one prompt template.
- **Distributed inference** across the cluster is what buys acceptable latency from hardware that
  individually cannot deliver it.
- The interface is **multimodal**, because the target learners cannot all be assumed to read
  fluently in the language of instruction.

## What the constraint bought

Running locally removes the network from the critical path entirely, which changes the interaction
from request-response to something continuous. It also means learner data never leaves the
device — a property that is much easier to guarantee by architecture than by policy.
